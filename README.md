## What the page communicates

- Six service areas: resilience; customer, funds and IP protection; AI assurance; supplier assurance; sovereign technology; board and governance.
- Proposed 10-, 30-, 60- and 90-day delivery gates for an agreed scope.
- Dated, linked reference evidence, distinguished from client and production outcomes.
- Government, BFSI and Oil & Gas research contexts.
- A working priority selector, searchable 30-problem catalog and non-confidential collaboration intake.

## Maintain the website

The site is plain HTML, CSS and JavaScript. It has no third-party scripts, analytics, advertising, external fonts, or form-submission service.

1. Edit `index.html` for positioning, delivery gates and evidence cards.
2. Update `assets/services.json`, the visible problem catalog in `index.html`, and `docs/service-catalog.md` together when the service catalog changes.
3. Keep each numerical result linked to a dated report with method and limitations.
4. Update the review date and sitemap after an evidence review.
5. Add named client cases only after documenting the role, scope, permission to name the organization, baseline, measured result and attribution.

The website uses GitHub Pages from the `main` branch root. The engagement button opens the existing public GitHub issue form. It never sends a request automatically.

## Claim standard

The vCISO language describes the proposed advisory offering. Timelines are scoped targets with stated prerequisites. Published technical observations are synthetic reference-lab results; they do not establish successful client delivery, certification or financial savings. No government, bank or consulting-firm endorsement is asserted.

See [the evidence register](docs/evidence-register.md) before changing outcome claims.
